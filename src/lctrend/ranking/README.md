# Получение ответа: отбор кандидатов и ранжирование

> **Статус: не сделано.** Логику получения ответа пока не делаем. В этой папке лежит подготовленный функционал: заготовка, на которой её можно будет собрать. Готовым результатом она не является. Её выдачу (`/api/search`, `backtest-top15`) нельзя показывать как результат анализа.

Всё, что относится к получению ответа, собрано здесь. Остальной пайплайн (сбор, извлечение, граф, временной датасет и признаки) от этой папки не зависит.

## Что здесь лежит

| Файл | Что подготовлено |
|---|---|
| `scoring.py` | Правило отбора кандидатов на дату T (`rejection`) и причины отсева. Взвешенная сумма z-оценок признаков `export-features` (`score_rows`, `rank_snapshot`). Цитаты-обоснования (`evidence_quotes`). Бэктест precision@K против случайных выборок (`backtest`). |
| `search.py` | Ответ `GET /api/search` в контракте `frontend/src/api.js`: выбор области по запросу (домены, названия технологий), карточки сигналов, кэш графа (`SearchService`). |
| `signals.py` | Таблица слабых сигналов в формате аналитиков: кластеры близких кандидатов по эмбеддингам названий → досье из графа → LLM (`prompts/signal.txt`) называет нишу и пишет обоснования → код считает стадию, тренд, балл и источники (`build_cards`). |
| `export.py` | Запись таблицы в XLSX (нужен extra `[report]`), CSV или JSON: колонки «№, Технология (слабый сигнал), Область, Компании, Почему это слабый сигнал, Стадия развития, Тренд упоминаний, Балл (стадия+тренд), Источники». |
| `../resources/ranking.json` | Параметры: правило отбора, веса, подписи, размер объяснения, кэш API, бэктест. Файл лежит вместе с остальными каталогами, потому что они проверяются при старте (`core/catalog_validation.py`). Сейчас значения временные. |

Тесты лежат в `tests/ranking/`. Точки подключения: `frontend/server/app.py` (`/api/search`) и `cli.py` (`backtest-top15`).

## Таблица слабых сигналов (`signals-report`)

```powershell
python -m pip install -e ".[report]"
python -m lctrend signals-report --snapshot 2026-09-28 --output artifacts/signals.xlsx --output artifacts/signals.json
# Без модели (только досье), по одной области:
python -m lctrend signals-report --no-llm --query "финтех" --top-k 20 --output artifacts/fintech.csv
```

Кто что заполняет:

| Колонка | Источник |
|---|---|
| Технология (слабый сигнал) | LLM по досье: механизм + объект + сценарий, 5–15 слов. Без модели — название ведущего концепта кластера. |
| Область | LLM выбирает одно значение из `signals.areas`; неизвестное значение заменяется последним («Другое»). |
| Компании | LLM выбирает из организаций досье; имена, которых нет в досье, отбрасываются кодом. Сначала организации с ролью (developed_by, used_by, funded_by, рыночное событие), затем организации авторов. |
| Почему это слабый сигнал | LLM по фактам досье (документы, независимые источники, события, суммы). Без модели — сводка чисел. |
| Стадия развития | Код по свидетельствам зрелости (`reports_maturity_stage`): высшая стадия, с переходом «A → B», если стадия росла. Если свидетельств нет — стадия от LLM. Уточнение в скобках — от LLM. |
| Тренд упоминаний | Категория — код: датированные документы за последние 12 мес. против предыдущих 12 (`signals.trend`). Пояснение после тире — LLM. |
| Балл (стадия+тренд) | Код: Концепция 1 / Прототип 2 / Пилот 3 / Раннее внедрение 4 + Стабильный 1 / Растёт 2 / Растёт быстро 3 (Снижается 0). Эта формула совпадает с эталонной таблицей аналитиков в 92 из 100 строк. |
| Источники | Код: документы с рыночными событиями и утверждениями, затем самые новые; Markdown-ссылки. |

Кандидаты — те же, что в `rank_snapshot`, но `signals.max_stage_rank = 5`: «раннее внедрение» ещё считается слабым сигналом, массовое внедрение — нет. Модель может отклонить кластер (`is_signal: false`) — зрелые общеизвестные технологии и шум извлечения; такие кластеры попадают в `rejected` JSON-отчёта.

Факты для карточек даёт извлечение: предикат `reports_market_event` (раунд, выход из stealth, запуск продукта, поглощение, партнёрство, контракт, стандарт, регулирование, открытый релиз, публичный аудит), раунды стартапов как `reported_investment` + `funded_by` и более узкие названия технологий (`prompts/extract.txt`). Документы, обработанные до этих изменений, этих фактов не содержат — для полноты их нужно переизвлечь.

## Что не сделано

- Не выбрана методика ответа. Правило отбора и веса в `ranking.json` — черновые значения, а не обоснованный выбор.
- Нет обученного классификатора: метки пока одноклассовые.
- Результаты бэктеста не проверены на заполненном временном датасете.
- `/api/graph` для карты сигналов не реализован.

## Входные данные

Код читает готовые данные из `lctrend.graph`: `TemporalCorpus` и `build_snapshot_rows` (признаки на дату среза), `independence_groups` и `months_before`. Этот вход реализован и от статуса папки не зависит.
