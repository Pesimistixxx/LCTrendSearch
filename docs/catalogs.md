# Списки строк в парсерах

Списки вынесены в файлы данных, но их роли различаются. Перенос в JSON сам по себе не делает эвристику достоверной.

| Файл в src/lctrend/resources | Что за строки |
| --- | --- |
| sources.json | domains — словарь широких областей с русскими и английскими aliases для классификации метаданных. search_aliases отдельно задают поисковые запросы обходчика. Остальное: API, поля источников, организации, параметры разбиения текста. |
| extraction.json | generic_technologies — слишком общие названия. composite_rules выключены: соседство слов не доказывает составную технологию. Разделы assertions/economics содержат шаблоны кандидатов утверждений, отрицаний, планов, денежных слов и валют. |
| generic_terms.json | Широкие области и отрасли: все домены, области и подобласти OpenAlex и ручной двуязычный список (ИИ, финтех, биотех, медицина, энергетика, материалы, робототехника, транспорт). Technology/Method/Material, название которой состоит только из этих слов, становится Domain. Два термина слитно («battery management») — составное название, а не область. |
| money.json | Индекс потребительских цен США (FRED CPIAUCSL) и средние годовые курсы 29 валют к доллару (Всемирный банк) для перевода сумм в доллары базового года. Новые годы дописываются сюда. |
| resolver.json | explicit_aliases — явно заданные эквивалентные названия одного типа. Semantic-настройки действуют в режиме `llm`: эмбеддинги и cross-encoder предлагают сходство, которое требует проверки. Совпадающие инициалы не объединяют сущности. |
| graph.json, schema.cypher | Отображения ролей и типов связей, ограничения Neo4j. Это контракт хранения, не исследовательская база. |
| runtime.json | Технические значения по умолчанию: модель, параллельная обработка, размеры сборки и пути вывода (`training_output`, `features_output`). Параметры срезов и меток — только в dataset.json. |
| pipeline.json | Размеры связанных пакетов, лимиты контекста и вызовов, форматы файлов, разрешённые структурные метаданные, ограничения и предупреждения адаптеров. |
| llm_schema.json | Допустимые отношения, обязательные роли, типы участников и проверки числовых значений. Это контракт извлечения, не список технологий или трендов. |
| llm.json | Настройки клиента LLM, тайм-ауты, лимиты ответа, выключенный по умолчанию кэш. Модель и ключ задаются отдельно. |
| countries.json | Допустимые ISO 3166-1 alpha-2 коды стран и их названия (ru/en, CLDR + частые сокращения и прилагательные) для проверки извлечённых Country: label или цитата должны называть страну кода, иначе `country_code_mismatch`. |
| taxonomy.json | Виды концептов, кластеризация векторов, глубина дерева и признаки новизны на дату снимка. |
| ranking.json | **Заготовка, логика ответа не сделана** (код — `src/lctrend/ranking/`). ТОП-15 на дату T: правило отбора кандидатов, веса z-нормированных признаков `export-features` и их русские подписи, размер объяснения, кэш `/api/search`, параметры бэктеста precision@K. Веса проверяются по схеме признаков в тестах. |
| dataset.json | Даты снимков, горизонт исхода, классы источников, временное разделение выборки и параметры признаков. |
| prompts/extract.txt, prompts/review.txt | Инструкции двух LLM-стадий: извлечь атомарные утверждения с основаниями и независимо проверить их поддержку текстом. |

Кандидат Assertion означает непроверенное извлечённое утверждение. Это не технологический кандидат для рекомендаций. Совпадение regex не устанавливает истинность; отсутствие совпадения может пропустить факт.

Enums, состояния моделей, обработчики команд и схема исходного CSV-экспорта остаются программными контрактами. Логику получения ответа — отбор и ранжирование технологических кандидатов — пока не делаем. Подготовленный функционал вынесен в [src/lctrend/ranking/](../src/lctrend/ranking/README.md); значения `ranking.json` временные, а выдача `/api/search` не является результатом анализа.

Каталоги включены в пакет. Для локального переопределения используйте LCTREND_CONFIG_DIR: одноимённый файл заменяется полностью, остальные берутся из пакета. Изменения извлечения требуют явной переобработки документов.

## Участники, страны, зрелость и таксономия

`llm_schema.json` задаёт предикаты с ролями `organization`, `country`, `parent`:

| Предикат | Роли | Ребро в графе (только принятое, affirmed, reported/observed) |
| --- | --- | --- |
| developed_by | subject → organization | `(Technology)-[:DEVELOPED_BY]->(Company/University/Organization)` |
| used_by | subject → organization | `USED_BY` |
| funded_by | subject → organization | `FUNDED_BY` |
| developed_in | subject → country | `DEVELOPED_IN` |
| located_in | organization → country | `LOCATED_IN` (с `document_version_id`) |
| subtechnology_of | subject → parent | `SUBTECHNOLOGY_OF` |
| reports_maturity_stage | subject; `qualifiers.stage` обязателен, `qualifiers.trl` только если число стоит после маркера TRL/УГТ/уровня готовности в цитате | `(Technology)-[:HAS_MATURITY_EVIDENCE {stage, stage_rank, trl}]->(Chunk)` |

Каждое такое ребро несёт `chunk_id`, `quote`, `start`/`end`, `assertion_id`, `run_id`, `observed_at`. Проекции задаются в `graph.json → projections`. Сущность Country из текста получает `country_code` (ISO 3166-1 alpha-2): код становится именем концепта и связывается `SAME_AS` с узлом `Country` из метаданных. У видов из `llm_schema.json → grounded_label_kinds` label должен встречаться в цитате или её chunk (по ключу v2, то есть с точностью до регистра и падежа, или как синоним из `explicit_aliases`); иначе сущность получает `label_not_grounded` и отклоняется вместе со своими claims.

## Метаданные локальных файлов (sidecar)

Для файла `report.pdf` рядом можно положить `report.pdf.meta.json`. Все поля необязательны. Без sidecar дата публикации берётся только из HTML-тегов публикации (`citation_publication_date`, `article:published_time` и др.). Дата создания DOCX/PDF сохраняется как `metadata.file_created_at` и публикацией не считается. Дата загрузки датой публикации не считается. Документ без даты помечается `undated`: он виден в срезах только после загрузки и учитывается в общих количествах, но не входит в динамику (окна роста, всплески, `documents_last_year`) и не определяет `first_seen`. Число таких документов пишется в manifest выгрузки (`undated_documents`).

```json
{
  "title": "Обзор рынка сервисной робототехники",
  "published_at": "2025-11-20",
  "language": "ru",
  "document_type": "report",
  "source": {"name": "Минпромторг", "type": "government", "family": "regulatory", "reliability_tier": 3, "url": "https://example.org/report"},
  "authors": [{"name": "Иван Петров", "affiliations": ["ООО Роботех"]}],
  "organizations": [{"name": "ООО Роботех", "type": "company", "country": "RU", "role": "associated"}],
  "countries": ["RU"],
  "domains": ["Robotics"],
  "identifiers": {"doi": "10.1000/example"}
}
```

`document_type`: article, patent, repository, package, report, transcript, standard, job_posting, grant, regulatory, news. Откуда взято каждое значение, записано в `metadata.metadata_basis`.

## Лексический и смысловой слой сопоставления

1. Лексический: ключ v2 (`extraction/lexical.py`) + группы синонимов `resolver.json → explicit_aliases`, которые сравниваются по тому же ключу («больших языковых моделей» попадает в группу LLM, GaN — нет). Ключ: NFKC, `+`→plus и `#`→sharp до снятия пунктуации (C ≠ C++ ≠ C#), цифры отделяются от букв (GPT-4 = GPT4), похожие латинские и кириллические буквы сводятся к одному алфавиту, casefold, ё→е; аббревиатуры в капсе (2–5 букв: AI, ИИ, GAN, LED) не стеммятся, короткие аббревиатуры смешанного регистра сохраняют регистр (GaN ≠ GAN, LoRA ≠ LoRa); кириллица стеммится Snowball (`snowballstemmer`, обязательная зависимость), у латиницы снимается только множественное число; у Country ключ — только ISO-код. Technology, Method и Material — одно семейство видов: одно название в разных документах, записанное разными из этих видов, остаётся одним концептом. Новый концепт получает `concept_id = stable_id("concept", семейство, ключ)` (для группы синонимов — ключ первого имени группы), поэтому результат не зависит от порядка документов и совпадает у параллельных заданий. Вид внутри семейства — вид группы синонимов, иначе старший из встреченных (Technology > Method > Material); узел в графе только повышается в виде. `preferred_label` непроверенного концепта — самая частая форма (`label_counts`, при равенстве — наименьшая строка). Совпадение с единственным совместимым концептом — принятое тождество. Если ключ совпал у нескольких концептов (дубли), выбирается тот, у которого принятое имя точно совпадает с формой упоминания; иначе упоминание остаётся `ambiguous` и записывается рёбрами `MENTIONS {resolution_status: 'ambiguous'}` ко всем кандидатам (в признаки такие рёбра не входят), а дубли сливаются командой `merge-concepts`.
2. Смысловой (`resolver.json → semantic`): эмбеддинги GigaChat `EmbeddingsGigaR` (или локальный MiniLM) и cross-encoder. В режиме `llm` включён параметром `use_in_llm` (переменная `DEDUP_IN_LLM=0/1` переопределяет). Совпадение не склеивает концепты: упоминание получает свой provisional-концепт, а найденный кандидат записывается ребром `POSSIBLY_SAME_AS {score, cosine, review_status: 'pending'}` для проверки.
3. Недоступность эмбеддингов или cross-encoder не валит документ: сопоставление идёт лексически, слой повторно пробуется через 5 минут, причина пишется в `run.metadata.semantic`.
4. Векторы названий концептов видов из `embedded_kinds` сохраняются в `c.embedding` / `c.embedding_model`; векторный индекс `<label>_embedding` создаётся при первой записи, когда известна размерность. Таксономия использует кластеризацию в стиле TaxoGen без локального переобучения эмбеддингов. Она принимает только совместимые модели и размерности, исключает будущие документы и связи. Рост ветвей считает уникальные документы; разные публикации в один день остаются разными. Версия дерева зависит от векторов, документальных оснований и родительских связей.

## Дополнительные области, экономика и география

`belongs_to_domain` связывает технологию, метод или материал с `Domain` через `BELONGS_TO_DOMAIN`; `targets_market` — с `MarketSegment` через `TARGETS_MARKET`. Текстовый Domain связывается `SAME_AS` с единственным узлом каталога при точном совпадении канонического имени или его явного aliases. Нечёткое сходство названий не создаёт такого тождества.

`manufactured_in`, `tested_in`, `deployed_in` различают производство, испытание и внедрение. Они не выводятся из страны автора или организации. Country требует существующий ISO-код; наличие кода само по себе не доказывает правильность страны — это проверяется по исходной цитате.

`reported_cost`, `reported_investment`, `reported_revenue`, `reported_market_size`, `reported_savings` сохраняют денежные утверждения технологии: исходное `raw`, числовое `value`, `currency`, а также `unit` и `period`, когда они явно указаны. Денежные значения должны совпадать с текстом; валюты не конвертируются, голый `$` не превращается автоматически в USD. Regex распознаёт тысячи/миллионы/миллиарды и валюты USD/EUR/RUB/CNY/JPY как кандидаты. Финансовые основания `HAS_ECONOMIC_EVIDENCE` со статусом accepted создаются только после проверки LLM и только для affirmed, reported/observed утверждений. Прогнозы и планы сохраняются отдельно как утверждения и не становятся фактическими экономическими сигналами.

Общие названия вроде «искусственный интеллект» сохраняются как `ConceptCandidate`. Это позволяет проверять первоначальное упоминание, не выдавая его за конкретную технологию.

## Где ИИ расширяет контекст

Цикл находится в `src/lctrend/llm/pipeline.py`: извлечение → `context_requests` → `expand_context` → полное повторное извлечение → проверка → сопоставление концептов → публикация вызывающей стороной в Neo4j. `src/lctrend/llm/context.py` обрабатывает три инструмента:

| Инструмент | Откуда приходит контекст |
| --- | --- |
| read_chunk | Полный исходный блок текущего документа по chunk_id. |
| search_chunks | Буквальное совпадение в исходных блоках текущего документа. |
| search_graph | Полные блоки ранее успешно обработанных и опубликованных документов Neo4j через GraphStore.read_related_chunks; текущая версия исключается. |

`pipeline.json → graph_context` ограничивает дополнение тремя документами, четырьмя блоками и 6000 символами; длина запроса — до 200 символов. Общие лимиты payload и вызовов остаются в силе. Большой блок пропускается целиком, текст не обрезается. Причины пропусков, недоступность графа и результаты поиска записываются в trace обработки.

Материалы других документов поступают в `related_context.chunks` с идентификаторами версии, названием и locator. Их получают обе LLM-стадии в пределах бюджета. Проверяющая стадия отдаёт приоритет обязательным цитатам и исходному контексту текущего документа; пропуски вспомогательных блоков отмечаются в `review_context.omitted_related_chunk_ids` и trace. Если пропущенный контекст необходим для вывода, проверяющая модель должна вернуть unclear. Материалы других документов помогают интерпретации, но не могут служить цитатой для утверждения из текущего документа: проверка evidence по-прежнему допускает только его видимые исходные блоки. Поиск в интернете, получение новых документов и проверка новых источников этим инструментом не выполняются.

CLI и веб-сервер при старте запускают `core/catalog_validation.py`: проверяют структуру каталогов, regex, границы лимитов и согласованность предикатов, ролей и проекций. Ошибка сообщает путь проблемного поля. Изменение JSON не меняет уже записанные факты: документы нужно переобработать. Для этих дополнений новые ключи в `.env` не нужны; существующие Neo4j/LLM параметры используются повторно.
